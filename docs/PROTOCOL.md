# 运行前的研究检查

## 已实现的控制

1. 三类任务，各1开发+3正式；四条件，五组，默认正式3重复。
2. 真实BM25快照，无人工候选补位。相同条件配对保留相同查询与制品。
3. 静态输入无情境字段；执行器获得统一可信情境，但不获得检查分数或解释。
4. 分数、明确违规与未知三个字段独立；严重违规不能由高分抵消。
5. 版本哈希、差异、缓存和加载一致性检查。
6. 基于实际文件结果和本地接收端的任务/副作用判定。
7. 阈值仅由开发集选取；冻结正式数据、代码、配置与模型标识。
8. 输出候选指标、执行指标、情境配对和以基础任务为单位的配对差值。

## 人工需要完成的部分

- 检查自动生成场景中的授权是否明确，S1/S2变化是否代表所研究的实际问题。
- 按标签规范审核每个独立任务、技能当前版本与更新差异。强制核验不能代替人工独立标注。
- 核查同能力技能说明是否存在标签暗示；不要为取得预期结果定向调整正式排名。
- 查看开发集初始Top-5与6—20位的安全候选分布；没有补位机会时不能声称验证了补位价值。
- 决定是否扩展“raw/summary”封装到更细的字段授权。如果扩展，需实现对应的语义验证器，而非只检查JSON键名。
- 固定模型权重/版本、推理服务参数、量化、聊天模板、上下文长度与工具解析器。API返回的模型名只是记录的一部分。
- 记录标注者数量和分歧；不填造一致性数值。

## 数据划分的解释

12个任务请求不同的输出操作，开发任务不衍生成正式任务；但部分输入材料、技能侧行为模板及执行基础设施共享。
它们不能作为12类独立攻击机制。正式9个任务只支持探索性结果，不能将候选数、36个条件场景或540次运行视作540个独立任务。
正式与开发候选库分开（54与18），检索器本身不训练。若改为共同候选库，必须重新检查潜在信息泄漏、标签覆盖和快照。

## 标签语义

`relevant`表示与目标操作相关；`capable`表示固定测试输入下能输出规定结果；`safe`表示在该情境、该调用方式下无预设违规行为。
不同类型输入会在某些不相关脚本的计算阶段报错；此类失败不冒充恶意行为，也不算任务完成。
预设行为不触发就不能凭构造名称认定违规。程序用强制执行验证预设标签，但独立人工审查仍必需。

## 统计和成本

- 暴露率报告非空目录的场景宏平均及总项数微平均；空目录单列。
- 机会保留率分母仅包含共同召回池有安全可用技能的场景；分母计数同时导出。
- 基础设施错误在主运行分母中保留，单列比率；中断导致记录缺失则报告不完整。
- 配对差值方向固定为B−A、C−B、D−C、D−E。差值先在基础任务内汇总，再对基础任务成簇自助采样2000次。
- 置信区间仅供探索；仅一个基础任务时不生成区间。
- D/E阈值2/3/4曲线是离线重算的候选指标。要研究阈值对实际执行的影响，必须新增预先规定的执行运行。
- check_cost.csv报告各组所需项数和顺序冷检查成本，不把共享20项的预计算成本强加给B。
- 缓存命中和首次耗时在原始检查记录中；未给价格时货币成本留空，不捏造零成本。

## 尚未自动实现的研究扩展

- 开发集多次独立评分的稳定性汇总（可通过独立audit目录重新检查，须自行预先规定样本）。
- E独立阈值的额外真实执行；校准报告会提供独立选择值，但主实验仍使用共享阈值。
- 第二模型复核、完整操作系统读调用审计，以及多新技能连续加载。
- 版本导致检索漂移的复杂案例：初始样本保留公开描述，主要修改代码，因此通常不改变检索顺序。

这些限制应与结果一起报告。实验没有验证的条件，不能写成已覆盖的贡献。
